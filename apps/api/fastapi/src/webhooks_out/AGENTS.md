# webhooks_out domain — agent context

**Owner:** Barrels platform (ADR-0029, foundations slice PF6). Organisations register https receivers and get signed events. Not the inbound `src/webhooks` package (Resend), not CAP's webhook (`CapWebhook`).

- **Tables** (`webhooks` schema, main database, migration `webhooksout20261020`, `webhooks` in `_TRACKED_SCHEMAS`): `endpoint` (id `whe_<hex>`, organisation, https `url`, `description`, `event_types` array with `*` allowed, `secret_encrypted`, `status` active/disabled, `consecutive_failures`, `disabled_reason`) and `delivery` (id `whd_<hex>`, `endpoint_id`, `event_id`, `event_type`, `attempts`, `status` pending/succeeded/failed/dead, `response_status`, `last_error` of at most 300 characters holding no response body, `next_attempt_at`). Unique `(endpoint_id, event_id)`. Deliveries never store the payload: it lives in the outbox row and is cleared when the row is done.
- **Secrets:** `whsec_<urlsafe>`, Fernet-encrypted with `ORG_SECRET_ENCRYPTION_KEYS` (`src/utils/secret_box.py`; no keys is 503). Returned once by create and rotate (`WebhookEndpointCreated`), never listed, never audited (`audit.py` excludes `secret_encrypted` and `consecutive_failures`). Rotation replaces the secret immediately (no overlap).
- **Events** (`events.py`): `booking.created|cancelled|rescheduled`, `payment.succeeded|refunded`, `contact.erased`, each with a Pydantic data schema (`extra="forbid"`; identifiers, status and amounts only, no personal data). `ping` exists only for the test route. Adding events is additive.
- **Emitting:** `service.emit_event(session, organisation_id, event_type, data, event_id=None)` in the caller's transaction (no commit). It validates the data, skips organisations without the `webhooks` entitlement, creates one `delivery` and one `webhook.deliver` outbox row per active matching endpoint (dedupe key `<event_id>:<endpoint_id>`; pass a stable `event_id` when the same event can be emitted twice). It raises `ValueError` for an unknown type or bad data: a programming error. Bookings, payments and contacts are wired by the integrator, not here.
- **Delivery** (`delivery.py`, handler `webhook.deliver`, imported by the worker at startup and in `drain_outbox`): body `{id, type, created_at, organisation_id, data}`; headers `Barrels-Signature: t=<unix>,v1=<hex HMAC-SHA256 of "t.body">` (`src/utils/signing.py`, shared with CAP's `sha256=` signer), `Barrels-Event-Id`, `Barrels-Event-Type`; 10 s timeout; redirects never followed. 2xx succeeds; 410 disables the endpoint; other outcomes record the failure, commit it and raise `WebhookDeliveryError` so the outbox backs off and goes dead after 5 attempts. The handler commits its failure bookkeeping before raising because the outbox rolls the handler back; the cost is that the outbox row lock is released a moment early (a second worker could retry it, which at-least-once delivery already allows). After 15 failed attempts in a row across deliveries the endpoint is disabled, its delivery ends dead, and owners and admins get a transactional email through `notifications.outbox_handlers.enqueue_email`. Later events skip disabled endpoints; queued ones end dead with `endpoint disabled`.
- **SSRF guard** (`ssrf.py`): https only, no credentials or fragment, no `localhost`; every resolved address must be globally routable (private, loopback, link-local, CGNAT, multicast, reserved, IPv4-mapped and 6to4 forms are refused, and one bad address in the answer refuses the host). It runs at registration (422) and on every delivery, and delivery connects to the validated IP with `Host` and TLS server name set to the hostname, so a rebinding DNS answer cannot redirect it. Tests replace `ssrf.resolve_host` and `delivery._client`.
- **Routes** (ADR-0025, tag `webhooks-out`): `/webhooks-out/org/*` use `require_org_app("webhooks", ADMIN)` (product `webhooks` in `entitlements.PRODUCTS`, which also creates the `webhooks.read|write` API-key scopes); another organisation's endpoint is a 404. `POST .../test` sends a `ping` synchronously through the same signer and reports the result without touching failure counters. Superuser routes: `GET /webhooks-out/admin/endpoints` (`organisation_id` filter) and `POST .../{endpoint_id}/disable` (reason required). Limit: 20 endpoints per organisation (409).
- Services flush, routers commit. Never log secrets or payload bodies.
