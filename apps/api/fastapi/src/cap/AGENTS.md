# cap domain — agent context

**Owner:** GMS operational service (warnings). Barrels maintains the code; GMS owns warning policy and thresholds. Ported from WMO's cap-composer.

## Layout
`models.py` (alerts, areas, feeds, jobs, audit events, lifecycle enums), `service.py` (authoring, lifecycle, import, feeds; it re-exports the names below, so `service.<name>` still works), `common.py` / `mapping.py` (shared helpers, row-to-schema conversions), `public_queries.py` (public feed and warning queries), `admin_lists.py` (settings, catalogues, audit, integrations), `catalogue.py` (GMS hazard list, parish geocodes, product and colour labels; served by `GET /api/v1/cap/gms-catalogue`, which the desk reads, so there is no copy in gaa-admin), `validation.py` + `xml.py` (CAP 1.2 XML), `xsd.py` (official CAP 1.2 schema check, file in `standards/`), `sign.py` (XML signing), `geo.py`, `pdf.py`, `images.py`, `cache.py` (public feed cache), `tasks.py` (enqueue publish side-effects), `profiles.py`/`profile_router.py` (hazard profiles).
Routes: authenticated `/api/v1/cap/*` and `/api/v1/hazard-profiles/*`; **public, unauthenticated** `/api/cap/*` (`public_router`, no `/v1`).

## Invariants
- Lifecycle per ADR-0023 (supersedes ADR-0013's self-publish): `DRAFT` -> `SUBMITTED` -> `APPROVED` -> `PUBLISHED` -> `EXPIRED`/`CANCELLED`. `publish_alert` needs `APPROVED` and an `approve` audit event. The author may approve their own alert (owner decision 2026-10-25, amending ADR-0023: one forecaster can issue an alert for GMS; colleague reviews are optional and recorded in the audit trail). Editing a Submitted/Approved alert resets it to `DRAFT`. Issue Update (`POST /alerts/{id}/updates`, `service.issue_update`) copies a published Alert or Update into a draft Update that references it with the stored `sent` (never a JSON round trip: that drops microseconds and the publish-time reference check would fail); it keeps status, sender and scope, refuses imported or non-conforming alerts, and returns the open Update already being prepared instead of a second one (row lock on the original). `emergency_publish_alert` (`cap.alert.publish_emergency`, role `cap-duty-supervisor`) publishes without approval, needs a non-empty reason and writes an `emergency_publish` audit event; never add another bypass. Holders of approve/publish/emergency permissions are privileged for MFA (`src/auth/privileged_mfa.py`). Alerts link to their source bulletin.
- Public feeds only expose published, in-scope alerts (`tests/cap/test_cap_public_scope.py`). After any publish/withdraw, invalidate the cache keys in `cache.py`.
- XML must validate against the official CAP 1.2 schema (`standards/CAP-v1.2.xsd`, `xsd.py`) before a normal publish. A non-conforming normal publish is refused with 422 (logged). **Emergency publish and cancellation are never blocked by a schema mismatch**: a real warning has to go out and a false one has to be cancellable. On a mismatch they publish anyway, return it as `snapshot.schema_mismatch` (emergency publish), record `schema_mismatch` in the audit entry, log an error (Sentry, no personal data) and notify the duty supervisor (`gms.cap_format_problem`). This is a deliberate, audited path, not an approval bypass: approval rules are unchanged (ADR-0023). Illegal XML characters are refused on save (422 naming the field; vertical tab and form feed become newlines); if any reach publish they are stripped before the XML is checked. NaN and infinity are refused for heights and coordinates.
- Imports: only malformed XML and a DTD are refused (400). Anything else that breaks the schema, or that had to be changed to be stored (`import_coerce.py` returns each change), is stored with `schema_conformant = false` and every problem in `schema_error`. Feed entries follow the same rule. `import_source` marks a feed or manual import. Publishing an imported alert, normal or emergency, needs `confirm_imported: true` (409 without it). Feeds and entries use the SSRF guard on every fetch, read at most 5 MB, and skip a bad entry without stopping the feed.
- Public routes (`/api/cap/alerts`, `/alerts/{identifier}`, `/past`, `/latest-active`) return `CapAlertPublicView`, which leaves out `schema_conformant`, `schema_error`, `import_source`, `created_by_user_id` and `updated_by_user_id`. `note` stays: the CAP XML publishes it. Staff routes keep the full `CapAlertPublic`; the desk's detail page reads `GET /api/v1/cap/alerts/by-identifier/{identifier}`. URL and feed fetches go through `safe_fetch.py` (https only, connect to the checked address, no redirects, size cap). A feed URL is checked when it is saved (`validation.validate_feed_url`: https, no credentials, no literal private host, no DNS; refusal is a generic 422). A feed's `last_error` is a generic class message (`host refused`, `could not fetch`, `ingest failed`); the detail is logged. Settings `web` must be an https address and `contact` plain text (no control characters or angle brackets); the settings audit payload lists changed fields and masks `signing_certificate_ref`.
- Side effects (PDF, social image, static map, webhooks) run in the ARQ worker through `CapJobEvent` rows (`src/worker/publishers.py`) with retries. Don't run them inline in a request. Email and browser push (`publish.email`, `publish.push`) are the same kind of job and live in `src/worker/cap_email.py` and `cap_push.py`. MQTT and WIS2 are not queued: `tasks.NOT_CONFIGURED_CHANNELS` reports them as `not_configured` in the integrations view (owner decision 2026-10-30: MQTT not planned; WIS2 once the local wis2box is live). Never queue a job for a channel with no publisher.
- GMS alerts are green only (ADR-0051); yellow, orange and red are CAP warnings. `escalation.py` turns one saved GMS alert revision into a pre-filled CAP draft ("Raise to warning"): `GET`/`POST /api/v1/cap/escalations`, needing `cap.alert.read` / `cap.alert.create` plus product access to the alert's kind. Warnings can also carry an optional `GMS:sectors` info parameter (comma-separated keys from `src/sectors.py`, validated by `levels.validate_sectors`; no tag means the warning affects everyone) that feeds Plan your week via `wxproducts/advisories.sector_outlook`. The draft links back through the three `GMS:source-bulletin-*` parameters. A repeat raise returns 200 with the existing open (draft, submitted or approved) warning (`created: false`, whatever colour was asked; the colour is changed in CAP), and a transaction-scoped advisory lock keyed on the product makes two simultaneous raises create one draft. The green alert stays in force until a forecaster withdraws it. The wording (event names, certainty, severity from the colour) is a first draft that GMS must sign off. `escalation.py` imports `wxproducts.service` only, never `wxproducts.advisories` (which imports `cap.service`).
- Don't change thresholds, wording policy or dissemination targets without GMS approval. The hazard list in `catalogue.py` is authoring suggestions, not approved thresholds or event codes. Change it through a reviewed code change and the snapshot in `tests/cap/fixtures/gms_catalogue.json`, never in the web app.

## Module boundaries
Imports point one way: `common` and `mapping` ← `public_queries` and `admin_lists` ← `service`. Never import `service` from those modules. Tests patch `service.invalidate`, `service.public_warnings` and `service.public_latest_active`, so the lifecycle functions that call `invalidate` stay in `service.py`, and nothing in `public_queries.py` may call `public_warnings` or `public_latest_active` itself: a patch on `service` would not reach it.

## Tests
`tests/cap/` (state machine, validation/XML/geo, signing, feeds, public scope, PDF, images, pagination). The schema has two suites: `test_cap_xsd_corpus.py` (every real shape conforms) and `test_cap_xsd_refusal.py` (non-conforming documents are refused).
