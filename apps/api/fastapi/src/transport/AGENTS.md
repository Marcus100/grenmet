# transport domain — agent context

**Owner:** GAA Transport department module (staff bus service).

- Backs the gaa-admin bus admin portal (`/bus`, `/bus/timetable`, `/bus/stops`) and, next, a separate driver app and staff app. Keep this API the single source for all three.
- Separate, self-contained database with its own Alembic history (`alembic.ini`, `migrations/`); no references to HR/CAP/weather tables. Staff identity is an auth `user_id` UUID, never a cross-database FK.
- Migrations are hand-written SQL (`NNNN_<slug>.py`, revision `transport_NNNN`); `downgrade()` deliberately raises because the catalogue is retained data. Keep migrations **additive**; retiring columns/tables needs its own approved migration.
- Models: `models.py` on `transport_metadata` (separate from the main DB, like `src/wxproducts/models.py`). Mirror the migrations; never autogenerate.
- **Timetable (`timetable/`, `transport_0003`):** routes, shifts, stops and service calendars are a registry edited in place; trips (`timetable_trips`) and stop times (`timetable_stop_times`) belong to a `timetable_versions` row. One draft at a time → publish with an effective date (today or later, Grenada). In force = latest published effective date ≤ today, latest `published_at` on a tie. Times are seconds after service-day midnight (may pass 24:00). `error` issues block publishing; `warning` issues don't.
- **Legacy v1:** `trips` / `trip_stops` and `GET /transport/spec` (deprecated) are frozen; migration 0003 copied them into version 1. Nothing new should read them.
- Permissions: `transport.*` keys and roles `transport-officer`, `transport-duty-manager`, `transport-contractor-supervisor`, `transport-viewer`, `transport-driver`, `transport-rider` in `src/auth/permissions.py`. `GET /transport/access` tells clients which controls to show; services enforce each key. Published timetable and catalogue are readable by any signed-in user.
- Tests: `tests/transport/test_router.py` (v1 spec, migration 0002), `tests/transport/test_timetable.py` (migration backfill, seeder, draft → publish lifecycle, permissions, registry). Seeds: `scripts/seed_catalogues.py` from `seed/transport-routes.csv` (also fills version 1 on a fresh database).
- **Roadmap (approved 2026-09-25):** phase 2 contractor fleet, drivers and inspections; 3 dispatch/runs and the Today board; 4 riders (registration + approval, QR check-in), reports, service alerts; 5 live location from the driver's phone during a run (raw points kept 30 days), ETA, automatic exceptions; 6 analytics and contractor scorecard; 7 AI ops assistant after the ADR-0014 `ai` domain. One contractor supplies buses and drivers; drivers sign in with auth accounts (no HR profile). See `docs/products/janitorial-and-transport-data-model.md`.
- **Source data status (2026-09-23):** confirmed with GAA — Route 1 Sunday/holiday morning return departs 6:15 a.m.; stop spellings Perdmontemps, Vincennes, Windsor Forest, Mt. Cuma (migration `transport_0002`); "Boca" and "The Bocas" are different stops. **Awaiting GAA HR:** Route 6 departure times (memo summary 3:30 a.m./12 noon/8:30 p.m. vs detailed list 4:30 a.m./1:00 p.m./9:30 p.m.; the app shows the detailed list, trips flagged `awaiting_confirmation`), the spelling of "Toco Bay", and whether Route 4 also serves shift workers. Don't change these without confirmation.
