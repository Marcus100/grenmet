# models_guidance domain — agent context

**Owner:** Barrels platform, for the GMS Dashboard (`apps/web/gmsdash`). Raw numerical-model point guidance, always labelled "Raw model guidance, not an official GMS forecast". Never present it as a GMS product forecast.

- **Sources:** ECMWF open data IFS and AIFS Single (0.25 degrees, `ecmwf-opendata`; licence CC-BY-4.0, attribution is returned with every meteogram and must be shown) and NOAA GFS 0.25 degrees (NOMADS GRIB filter over `httpx`, public domain). `providers.py` holds one fetcher per source behind the `RunFetcher` protocol. ECMWF cannot be sub-setted by area, so runs download in 8-step chunks, are read and deleted; GFS asks NOMADS for a small box per forecast hour. Raw GRIB lives only in a temporary directory.
- **Cadence:** IFS 3-hourly to 144 h then 6-hourly to 240 h, only the 00/12 UTC cycles (the 06/18 cycles stop at 90 h); AIFS 6-hourly; GFS 3-hourly. `HORIZON_HOURS` (default 240) caps all of them.
- **Extraction (`extract.py`):** reads GRIB with ecCodes directly and takes the nearest grid cell per point. cfgrib/xarray were tried and dropped: GFS files carry overlapping APCP windows (0-6 and 3-6) that cfgrib merges away. Precipitation per interval comes from `(startStep, endStep)` windows: a direct window, or the difference of two windows sharing a start. Units: temperature degC, wind m/s (direction is where it blows *from*), MSLP hPa, cloud %; ECMWF `tp` metres and `tcc` fraction are scaled, GFS already is mm and %.
- **Storage:** `model_guidance_run` (model, cycle time, unique) and `model_guidance_series` (JSONB arrays per point). Main database, no schema. A run is stored in one transaction only when every step downloaded, so a failure leaves nothing and the next hourly check retries. `service.prune` deletes runs older than `RETENTION_DAYS`.
- **Worker:** `fetch_model_guidance` (`src/worker/main.py`) runs hourly at `MODELS_GUIDANCE_POLL_MINUTE`, timeout 3600 s, and is a no-op unless `MODELS_GUIDANCE_ENABLED` (default off: a run is hundreds of MB). One model failing is logged (Sentry) and never blocks the others.
- **Access (`dependencies.py`):** `GET /models/catalogue` and `/models/meteogram` accept (a) a member of an organisation holding `org.organisation_app` `gmsdash` enabled, with `X-Barrels-Organisation`, using a `gmsdash` app token or an account token, or (b) GMS staff with `gmsdash.guidance.view` and no organisation header. Not a member 404, member of a non-entitled organisation 403, other apps' tokens 401. `/models/organisations` and `/models/access` need membership only; creating a request needs organisation admin/owner.
- **Access requests:** `model_guidance_access_request` (one pending per organisation). Staff with `gmsdash.access.review` list and decide (`/models/access-requests`, `/{id}/decision`); approval calls `organisations.service.set_app_enabled(..., "gmsdash")`. There is no admin UI yet; staff use the API (or `PUT /organisations/{id}/apps/gmsdash` in the Barrels admin console).
- **Roles:** `gmsdash-member` (granted on first sign-in, `app.gmsdash.access`) and `gmsdash-operator` (staff: both `gmsdash.*` permissions).
- **Points:** `MODELS_GUIDANCE_POINTS` (JSON) overrides the defaults in `config.py` (MBIA, Lauriston/Carriacou, Petite Martinique). Point keys are the API identifiers.
- **Tests:** `tests/models_guidance/` — synthetic GRIB written with ecCodes (`grib.py`), extraction and accumulation windows, mocked NOMADS (`httpx.MockTransport`), ingest and pruning, access control (entitled, not entitled, cross-organisation, staff, other app tokens), access-request flow. No live network.
