# cms (`@barrelsgd/web-cms`) — agent context

Port **3006**. Payload CMS for GMS editorial content (GMS is the client; Barrels delivers). Weather operations stay in gaa-admin/FastAPI; this app never creates or publishes operational products.

**Boundary:** FastAPI owns real data on the GMS site (observations, forecasts, products, reports, datasets, imagery). The CMS holds only editorial / social content (stories, desk notices, Q&A, history, quizzes, facts, the forecaster's note). If a field is measured, issued or operational, it belongs in FastAPI.

## Architecture
- **Never put a test file in `src/migrations/`**: Payload imports every file in that folder when it runs migrations, so a `*.test.ts` there crashes `pnpm db:migrate` (found 29 Oct 2026). Migration tests live in `src/lib/`.
- Payload config: `src/payload.config.ts`. One bounded collection per GMS homepage section, built by `collections/editorial.ts` from shared parts in `src/fields/` (workflow + review hook, fixed slugs, cover, topics, links, SEO, social): `desk-updates` (From the Desk), `stories`, `questions` (Questions about the weather; optional science check), `discover` (On this day, quiz, Did you know, sky note; one `type` field shows that type's fields), `report-notes` (Latest reports: a write-up of one issued report) and `live-posts` (Weather now feed: the duty forecaster's note as kind `note`, a general update, or a YouTube/Facebook/SoundCloud link validated by `lib/media-links.ts`). **Related links are pasted, not picked** (owner, 28 Oct 2026): `relatedLinksField` in `fields/common.ts` is a list of `url` + optional `title`/`category` + `isMain`. `lib/editorial-links.ts` reads each address with `recognizeLink` from `@barrelsgd/gms/link-recognition`: an issued product (`/weather/issued/<id>`), a warning (`/alerts/<identifier>`), another GMS page, or an outside link, and `validateRelatedLinks` (`fields/common.ts`) fills blank titles/categories from FastAPI (`lib/link-titles.ts`, 3 s timeout, plain-label fallback), allows one main link (never an outside link) and, for report write-ups, requires a main issued product. **Social sharing** (`socialField`) shows download buttons for the main link: a published warning's social image, PDF and map, fetched on click by the staff-only `GET /api/social-attachment?identifier=&kind=` (`lib/social-attachments.ts`, from the warning system on `AUTH_API_URL`; nothing is stored), plus an optional custom `image` upload (columns `social_image_id`). Forecasts and bulletins have no generated images yet. The old `linkedProduct` field and its picker are gone; its columns stay in the database (a migration copied each into a main related link). Never copy product figures into a CMS field. All of them sit in one admin group, **GMS Content**, in the weather site's top-to-bottom order (Live posts, Desk updates, Report write-ups, Stories, Questions, Discover, then the globals). The duty forecaster's note is a live post of kind `note` (owner, 29 Oct 2026): signed (its author and publish time), expiring at the next 07/12/18 AST issue unless set, posted by `cms.weather-now.note` holders without the review step (`lib/duty-note.ts`, `collections/live-posts.ts`). Its CAP alert is a main related link. The public feed still answers `weatherNow.note` (with `alertUrl` for older GMS builds), built from those posts by `findWeatherNow`; `note` posts never appear in `livePosts`, so older GMS builds keep parsing. The old `weather-now` global is legacy: hidden, no access, and its table stays until the owner approves dropping it (its last note was copied by `20261029_030000_duty_note_to_live_posts`). One global remains, `homepage` (labelled "Hide homepage sections": only `hiddenSections`, the emergency switch; wording and the News card choice are no longer editable, the feed sends the standard wording; slug kept so no table is renamed). The Stories collection is shown as **News** (homepage heading "Weather news") and the Discover collection as **Discover** (owner, 28 Oct 2026). What leads a section is set on the posts (owner, 28 Oct 2026): `leadOnHomepage` on Stories (one lead, enforced by a field check) and `featured` + `featuredOrder` on Questions (up to five), in `fields/homepage-placement.ts`, settable only with `cms.homepage.manage`. "Plan your week" (Explore today) is no longer edited in the CMS. A desk update's `kind` is "About": the GMS product or service it covers (forecasts, tropical outlook, bulletins, CAP warnings, marine, aviation, climate, service notice, community, announcement); a story's `kind` is its topic; a live post's `kind` is the Weather now tab it belongs to (`note` is the duty forecaster's note; a general update sits beside it; Satellite, Radar, Wind or Seas as a note under that tab; or Video/Audio to play). There is no word filter: editors may write "warning", "watch" or "advisory" freely (owner, 29 Oct 2026; the earlier hazard-word guard was removed). Plus `media`, `users`. Slugs carry a collection prefix (`updates/`, `stories/`, `questions/`, `discover/`); GMS maps each to its own route (`/explore/updates`, `/explore/news`, `/explore/explained`, `/explore/quiz`) with `contentHref`/`questionHref` in `apps/web/gms/src/lib/cms.ts`.
- **Include in newsletter** (`includeInNewsletterField`, `fields/common.ts`; sidebar tick, publishers of the section only; on live posts only for kind `update`) feeds the daily digest. `GET /api/public/newsletter` (`lib/newsletter-feed.ts`) returns the ticked posts published in the last three days as `{"items": [{title, url, summary, includeInNewsletter, publishedAt}]}`, the shape FastAPI reads in `apps/api/fastapi/src/subscriptions/newsletter.py` (set FastAPI's `NEWSLETTER_POSTS_FEED_URL` to it). URLs are built from `GMS_SITE_URL` and the weather-site routes in `lib/gms-site.ts`, which a test pins to the GMS client's `ROUTES`. Without `GMS_SITE_URL` the feed answers 503 and the digest carries no posts.
- **Approve for social** (`socialField(publishKey)`: `social.approveForSocial`, publishers only) with publication fires `distributeForSocial` (`lib/social-distribution.ts`, in each editorial collection's `afterChange`). It sends only when the post is published, approved, a supported platform is chosen (Facebook, Instagram, WhatsApp Channel; X, YouTube and LinkedIn stay copy-and-paste), and `CMS_DISTRIBUTION_SECRET` and `GMS_SITE_URL` are set. The POST goes to `{AUTH_API_URL}/api/v1/content-distribution/internal/posts` with `X-CMS-Secret`. FastAPI keys each post `cms:<collection>:<slug>:<platform>`, so every save of an approved post sends the same body and a re-save cannot double-post. A failure is reported as `cms-social-distribution` and never blocks publishing. The image is the custom social image, else the cover. The shared starting caption is not sent; each platform's own copy is.
- Dedicated `gms_cms` database and role inside the shared Postgres (`pnpm cms:setup-db`, idempotent). Payload migrations live in `src/migrations/`; the runtime graph for CI migration checks is `packages/cms-migrations`.
- Identity is **FastAPI's**: `src/lib/fastapi-strategy.ts` + `fastapi-identity.ts` authenticate explicitly granted accounts through a CMS-scoped session. Access rules in `src/access.ts` use FastAPI permission keys: `PUBLISH_KEYS` (`cms.publish.<collection>`) per section, plus `cms.article.create`, `cms.article.edit.all`, `cms.article.manage`. New keys go in `apps/api/fastapi/src/auth/permissions.py`.
- Public feeds (anonymous, published only, no staff fields; shaped in `src/lib/public-feed.ts`): `GET /api/public/home` (every homepage part; each fails independently), `GET /api/public/articles?collection=&slug=`, `GET /api/public/questions?slug=&topic=` and `GET /api/public/quizzes?slug=` and `GET /api/public/newsletter` (ticked posts for the digest, above). Latest reports and imagery are FastAPI data (reports come from `/wxproducts/public/products`), never CMS fields. Health: `/api/health`, `/api/ready`.
- Every public read goes through `liveWhere` (`src/lib/publication-window.ts`): published, and inside the optional show-from and take-off times (`publishAt`, `unpublishAt`). The times are checked when a reader asks; there is no job runner, and Payload's `schedulePublish` is not used (it needs `versions.drafts`, which these collections do not enable). `GET /api/public/preview?token=` serves one draft for a signed token (`lib/preview-link.ts`: two hours, key derived from `PAYLOAD_SECRET`, `noindex`, `no-store`). `GMS_PREVIEW_URL` turns on the admin Preview button. The weather site's page at that address (`apps/web/gms/src/app/(pages)/preview`, `noindex`, `no-store`) reads the token through this endpoint and renders articles (desk updates, stories, report write-ups) with the published article's own body. Forged or expired tokens get the endpoint's 404; questions and live posts are not previewed on the site yet.
- Audit and checks: every editorial save writes `publication-log` records (`lib/publication-log.ts`; editors read them, nobody edits). Staff-only `GET /api/broken-links` (`lib/broken-links.ts`) lists related links whose product, warning or page is withdrawn or missing, using the same resolver the editor uses (`checkLink` in `lib/link-titles.ts`).

## Rules
- **CMS admission:** only system administrators grant `none`/`writer`/`publisher` in GAA Admin Users. Department and legacy Payload roles never grant access; CMS tokens must remain isolated from staff APIs.
- Env through `src/env.ts` only. New: `GMS_SITE_URL` (the weather site's public origin, for newsletter and social links) and `CMS_DISTRIBUTION_SECRET` (at least 32 characters, shared with FastAPI as `X-CMS-Secret`). Neither is written to any `.env` file by agents.
- Payload's migration loader loads this config without Sentry. Lib modules that the config imports must load `./report-error` lazily (as `lib/social-attachments.ts` and `lib/social-distribution.ts` do).
- After changing collections, run `generate:types` and `generate:importmap` and commit the generated `payload-types.ts` / import map. Commit them exactly as Payload writes them: Biome ignores both (`biome.jsonc`), so the dev server's rewrites never fail `check:ci`.
- Schema changes need a Payload migration. Additive migrations within the authorized task may proceed; ask first for destructive schema/data or breaking changes per root AGENTS.md. Older migrations were hand-written without snapshots; `20260929_210000_editorial_collections.json` is the current snapshot, so `db:generate` now diffs correctly. Verify a new migration on a scratch database before committing.
- Publication requires the section permission; authors edit only their own unpublished content. Keep `src/access.ts` tests in step with any change.

## Commands and tests

```bash
pnpm --filter @barrelsgd/web-cms seed:editorial        # starter questions etc. as Ready for review (idempotent; needs one CMS editor)

pnpm --filter @barrelsgd/web-cms test              # unit
CMS_TEST_DATABASE_URL="$DATABASE_URL" pnpm --filter @barrelsgd/web-cms test   # + integration (isolated schema)
```
