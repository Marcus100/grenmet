# Public weather data feeds

## Published weather products
The API exposes `GET /api/v1/wxproducts/public/products` for current published products and `GET /api/v1/wxproducts/public/forecast` for public forecast selection. Use the service base address configured for the intended environment; these are API paths, not documentation-site paths.

Check issue and validity times. A draft saved in the staff portal is not automatically a published product.

## CAP warnings
`GET /api/cap/warnings` supplies the public warning presentation. The CAP service also exposes public alert, XML and RSS routes. Read each message's status and validity: a test or exercise message must not be presented as an actual warning.

Keep alert identifiers and update/cancellation relationships when consuming CAP messages. Do not interpret an unavailable feed as an empty active-warning list.

## Read access versus publishing
Public read endpoints do not authorise alert creation or publication. Those actions use authenticated staff workflows. Do not place staff credentials in public websites or copied examples.

## Integration planning
The existence of a public feed does not configure a webhook, email subscription or downstream transmission. Confirm the required channel and receiving system separately. See [API parameters](/pagination).
