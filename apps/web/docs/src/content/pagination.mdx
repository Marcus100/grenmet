# Using the public API

## Choose the correct endpoint
Use the intended environment's API base address and the published endpoint contract. The [feed guide](/webhooks) lists the main public weather entry points. There is no general-purpose documentation-site API key or fictional SDK to install.

## Parameters differ by endpoint
Do not assume all list endpoints share one pagination scheme. The API's shared pagination dependency uses `page` (starting at 1) and `size` (default 100, maximum 1000), but only routes using that dependency accept those parameters.

The authenticated imported-observation endpoint `GET /api/v1/wxproducts/observations` instead accepts `kind`, `station`, `start`, `end` and `limit`. It is a staff endpoint, not a public feed. Staff-entered eRegister records are a separate collection.

## Dates and time ranges
Send date/time values in the format required by the endpoint. Include the UTC offset when supplying a timestamp. Grenada local time is UTC−04:00; do not treat a local midnight as UTC midnight.

## Handle failures
Check the HTTP status before parsing a successful response. Treat permission failures, invalid parameters and unavailable services distinctly. Retain the last known issue time when showing cached information, and make stale data visible to the reader.

## Confirm the contract
Developers should consult the deployed service's OpenAPI definition for exact parameters, enum values and response fields. A parameter on one route is not evidence that another route supports it.
