# Finishing touches

These are what separate "correct" from "designed". Reach for them once hierarchy, spacing and type are already right — they cannot rescue a page that fails higher up the ladder.

## Supercharge what is already there

You rarely need new elements; you need the existing ones to work harder.

- **Bullets → icons.** Checkmarks and arrows are safe generics; something content-specific is better — a padlock for a list of security features.
- **Promote quotation marks** in a testimonial into a visual element: much larger, in a lighter colour.
- **Style links** deliberately — colour and weight at minimum, or a thick coloured underline that partially overlaps the text.
- **Custom checkboxes and radios.** Using a brand colour for the selected state instead of the browser default is often the entire difference between boring and polished.

## Accent borders

A coloured rectangle requires no illustration talent and reliably makes a bland surface feel designed:

- across the top of a card
- against the active item in a nav
- down the left side of an alert
- as a short rule under a headline
- across the top of the whole layout

## Decorate backgrounds

When a page is correct but plain, add interest to a background rather than restructuring:

- **Change the background colour** to distinguish a panel or an entire page section. A slight gradient reads as more energetic — keep the two hues within about 30° of each other.
- **A repeating pattern**, at low contrast against the background. It need not cover everything; a pattern repeating along a single edge works well.
- **A shape or illustration** in a specific position — simple geometry, a fragment of a pattern, or something more considered like a simplified world map. Keep contrast low so it never competes with content.

## Empty states are not an afterthought

The empty state is the **first thing a user sees** of a new feature — before any of the carefully crafted sample data exists. Design it deliberately:

- Lead with an image or illustration to hold attention.
- Emphasise the call to action that gets the user to their first item.
- **Hide supporting UI** — tabs, filters, sort controls — that does nothing until content exists.

## Use fewer borders

Borders are one way to separate two elements, not the only one, and too many make a design feel cluttered. Before adding one, try:

- **A box shadow** — outlines the element like a border but far less insistently. Works best when the element is not the same colour as its background.
- **Two background colours** — slightly different backgrounds on adjacent elements is usually all the separation needed. If you already have both a border and differing backgrounds, drop the border.
- **More space.** The most direct way to create separation is to separate things.

## Think outside the box

Component conventions are habits, not requirements.

- A **dropdown** is just a floating box. It can have sections, multiple columns, supporting text, colourful icons.
- A **table** column that does not need to be sortable can be merged with a related one to introduce hierarchy inside the cell. Table cells can hold images and colour, not only plain text.
- **Radio buttons** that carry real weight in the UI work far better as selectable cards than as a stack of circles.

Constraints are valuable, but a component's conventional shape is not one of them.

## Keep levelling up

Two habits, from the book's close:

- **Look for decisions you would not have made.** When a design strikes you, find the specific unintuitive choice — the inverted datepicker background, the button placed inside the text input, the two-colour headline.
- **Rebuild interfaces you admire from scratch, without devtools.** Working out why your version looks different is how you discover the small rules — tighter leading on headings, tracking on caps, layered shadows — on your own.
